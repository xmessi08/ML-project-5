# ML Project — Logistic Regression and Cost-Sensitive Classification

## 📌 Описание проекта

В данном проекте исследуется алгоритм машинного обучения **Logistic Regression** для решения задачи бинарной классификации.

Цель проекта — оценить качество модели, построить ROC- и PR-кривые и найти оптимальный порог классификации с учётом стоимости ошибок.

В эксперименте ложно положительные ошибки (FP) и ложно отрицательные ошибки (FN) имеют разную стоимость. Поэтому стандартный порог классификации 0.5 сравнивается с порогом, который позволяет уменьшить общие потери.

## 🎯 Цели проекта

- Создать искусственный датасет для бинарной классификации.
- Обучить модель Logistic Regression.
- Разделить данные на обучающую и тестовую выборки.
- Оценить качество модели с помощью ROC-AUC и PR-AUC.
- Построить ROC-кривую и PR-кривую.
- Исследовать влияние порога классификации на стоимость ошибок.
- Найти порог с минимальными суммарными потерями.
- Сравнить результаты стандартного и оптимального порогов.

## 📊 Описание датасета

Для эксперимента используется искусственный датасет, созданный с помощью функции `make_classification`.

| Параметр | Значение |
|---|---|
| Количество объектов | 2000 |
| Количество классов | 2 |
| Доля класса 0 | 80% |
| Доля класса 1 | 20% |
| Размер обучающей выборки | 70% |
| Размер тестовой выборки | 30% |
| Размер тестовой выборки в объектах | 600 |
| Random state | 42 |

Датасет несбалансированный: объектов класса 0 значительно больше, чем объектов класса 1.

## ⚙️ Этапы выполнения проекта

### 1. Генерация и разделение данных

Создаётся искусственный датасет из 2000 объектов. Затем данные разделяются на обучающую и тестовую выборки в соотношении 70/30.

Параметр `stratify=y` сохраняет пропорции классов при разделении.

### 2. Обучение модели

Используется алгоритм `LogisticRegression`.

После обучения модель рассчитывает вероятности принадлежности объектов к положительному классу с помощью метода `predict_proba()`.

### 3. Оценка качества модели

Для оценки модели используются следующие метрики:

- **ROC-AUC** — показывает, насколько хорошо модель различает два класса при разных порогах классификации.
- **PR-AUC** — оценивает соотношение Precision и Recall при разных порогах.
- **Precision** — доля правильных положительных предсказаний среди всех положительных предсказаний.
- **Recall** — доля найденных положительных объектов среди всех реальных положительных объектов.
- **F1-Score** — гармоническое среднее Precision и Recall.
- **Accuracy** — доля правильных предсказаний среди всех объектов.

### 4. Построение ROC- и PR-кривых

Строятся два графика:

- **ROC-кривая** показывает зависимость True Positive Rate от False Positive Rate.
- **PR-кривая** показывает зависимость Precision от Recall.

Полученные значения площади под кривыми:

| Метрика | Результат |
|---|---:|
| ROC-AUC | 0.9639 |
| PR-AUC | 0.8782 |

Эти результаты свидетельствуют о хорошем качестве классификации на тестовой выборке.

### 5. Анализ стоимости ошибок

В проекте используются следующие стоимости ошибок:

| Тип ошибки | Обозначение | Стоимость |
|---|---|---:|
| Ложноположительная ошибка | FP | 10 |
| Ложноотрицательная ошибка | FN | 50 |

Ложноположительная ошибка возникает, когда модель ошибочно относит объект к положительному классу.

Ложноотрицательная ошибка возникает, когда модель не обнаруживает объект положительного класса.

Поскольку стоимость FN в пять раз выше стоимости FP, пропуск положительного объекта считается более серьёзной ошибкой.

Общая стоимость ошибок рассчитывается по формуле:

`Total Cost = FP × 10 + FN × 50`

### 6. Поиск оптимального порога

Проверяются 101 порог классификации в диапазоне от 0 до 1.

Для каждого порога рассчитывается общая стоимость ошибок. Затем выбирается порог с минимальными потерями.

В результате эксперимента оптимальным оказался порог **0.13**.

### 7. Сравнение результатов

Модель оценивается при стандартном пороге 0.5 и оптимальном пороге 0.13.

#### Порог по умолчанию: 0.50

| Показатель | Результат |
|---|---:|
| TN | 463 |
| FP | 16 |
| FN | 21 |
| TP | 100 |
| Потери от FP | 160 |
| Потери от FN | 1050 |
| Общие потери | 1210 |
| Accuracy | 0.9383 |
| F1-Score для класса 1 | 0.8439 |

#### Оптимальный порог: 0.13

| Показатель | Результат |
|---|---:|
| TN | 403 |
| FP | 76 |
| FN | 4 |
| TP | 117 |
| Потери от FP | 760 |
| Потери от FN | 200 |
| Общие потери | 960 |
| Accuracy | 0.8667 |
| F1-Score для класса 1 | 0.7452 |

## 📈 Итоговое сравнение

| Показатель | Порог 0.50 | Порог 0.13 |
|---|---:|---:|
| Ложноположительные ошибки (FP) | 16 | 76 |
| Ложноотрицательные ошибки (FN) | 21 | 4 |
| Общие потери | 1210 | 960 |
| Accuracy | 0.9383 | 0.8667 |
| Recall класса 1 | 0.8264 | 0.9669 |
| Precision класса 1 | 0.8621 | 0.6062 |

Оптимальный порог уменьшил общие потери с 1210 до 960, то есть на **250 единиц, или примерно 20.66%**.

При пороге 0.13 модель обнаруживает больше объектов положительного класса и сокращает количество пропусков с 21 до 4.

Однако количество ложноположительных ошибок увеличивается с 16 до 76. Также снижаются Accuracy и Precision класса 1.

Это показывает, что выбор порога зависит от задачи и относительной стоимости ошибок.

## 📝 Выводы

В ходе проекта была обучена модель Logistic Regression для бинарной классификации.

Значение ROC-AUC составило 0.9639, а PR-AUC — 0.8782, что указывает на хорошую способность модели различать классы.

При стандартном пороге 0.5 общие потери составили 1210 единиц. После подбора порога с учётом стоимости ошибок оптимальным оказался порог 0.13, при котором потери снизились до 960 единиц.

Хотя при новом пороге Accuracy уменьшилась с 0.9383 до 0.8667, количество ложноотрицательных ошибок сократилось с 21 до 4.

Таким образом, **максимальная Accuracy не всегда означает минимальные потери**. В задачах, где пропуск положительного объекта обходится дорого, снижение порога классификации может быть более эффективным решением.
